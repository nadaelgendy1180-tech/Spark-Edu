# Spark Edu — استيراد 7 برامج واشتراكات شهرية (7 نوفمبر 2026)

## ماذا تضيف هذه النسخة؟
- رفع ملف JSON واحد **من لوحة إدارة ندي الجندي** لإضافة البرامج والمجالات والأهداف إلى Firestore على دفعات؛ لا يحتاج سكربت على جهاز المدير ولا ملف مفتاح Firebase خاص.
- المصدر السابق: **7 برامج، 121 مجالًا، 2842 هدفًا**. البيان موجود في حزمة PRIVATE مستقلة عن أكواد GitHub.
- تعرف البرنامج الذي أضفته يدويًا باسم «بورتاج (Portage)» وتستخدم سجله بدل إنشاء برنامج بورتاج ثانٍ.
- الاستيراد قابل للإعادة بعد انقطاع الاتصال: يتجاوز السجلات الموجودة ولا يستبدل النصوص التي عُدّلت من الإدارة.
- **إدارة المنصة:** إنشاء مشترك جديد بالاسم والبريد وكلمة مرور يختارها المدير، وبدء اشتراك لمدة 30 يومًا. حساب الدخول يُنشأ في Firebase Authentication، والسجل والصلاحيات في Firestore.
- عرض: مفعّل / غير مفعّل / منتهي / موقوف، تاريخ انتهاء الاشتراك والمدة المتبقية، وعدّاد الاشتراكات القريبة من الانتهاء خلال 7 أيام، والبحث والتصفية.
- عند انتهاء المدة تُقفل وظائف المنصة الخاصة بالمشترك لكن تبقى بياناته محفوظة؛ يمكن تجديده من لوحة المدير ويستعيد الوصول فورًا.
- المستخدم يستطيع إرسال طلب تجديد من داخل الموقع؛ الطلب يظهر في لوحة الإدارة، ويُستكمل بقرار المدير. لا توجد مدفوعات تلقائية أو بريد تلقائي.
- إنشاء المشترك لا يسجّل المدير خارج الموقع: يُستخدم Auth ثانوي بذاكرة مؤقتة. لا تُخزّن كلمات المرور في Firestore أو المستودع.

## ترتيب التفعيل — لا ترفع ملف البرامج إلى GitHub
1. خذ نسخة احتياطية من ملفات المستودع وقواعد Firebase الحالية قبل أي استبدال.
2. ارفع **محتويات** ZIP الخاص بتحديث كود GitHub إلى جذر مستودع `nadaelgendy1180-tech/Spark-Edu` مع الاحتفاظ بالمسارات. أهم الملفات: `src/App.tsx`، `src/programImport.ts`، `src/styles.css`، `firestore.rules`. ملف `.md` توثيق فقط. إذا اختلف الكود الحالي عن النسخة السابقة، ادمج التغييرات بدل استبدال آخر تعديلاتك دون مراجعة.
3. افتح Firebase Console → مشروع `speak-d6e7f` → Firestore Database → Rules، واستبدل القواعد **بالمحتوى الكامل** من `firestore.rules` ثم اضغط Publish. رفع ملف القواعد إلى GitHub وحده لا ينشرها على Firebase.
4. تأكد أن Vercel أنهى نشر المشروع بحالة Ready بعد رفع ملفات GitHub، وأن متغيرات `VITE_FIREBASE_*` الستة مضبوطة من قبل.
5. نزّل `spark-programs-PRIVATE.json` على جهازك (هو **الملف الواحد الذي يُرفع من اللوحة**). لا ترفعه أبدًا إلى GitHub، ولا إلى مجلد public أو إلى Vercel Environment Variables.
6. سجل الدخول إلى `spark-edu.vercel.app` بحساب ندي الجندي، ثم ادخل **إدارة المنصة → استيراد البرامج والأهداف دفعة واحدة**.
7. اختَر ملف JSON مباشرة، ثم اضغط **استيراد كل البرامج مرة واحدة**. اترك الصفحة مفتوحة حتى يظهر «اكتمل الاستيراد» مع عداد 7/7. في حال الفشل، اختر نفس الملف مرة ثانية.
8. **الاعتماد والنشر:** افتراضيًا تدخل الأهداف كمسودات غير معتمدة بسبب احتمال وجود أخطاء في النصوص المستخرجة من Word، وللتحقق من حقوق استخدام المواد. فقط إن كنت قد راجعت الأهداف وحقوق نشرها بالفعل، فعّل مربع الإقرار قبل الاستيراد لعرضها للمشتركين مباشرة. ويمكن إعادة استيراد نفس الملف لاحقًا مع تفعيل الإقرار لاعتماد البنود الموجودة دون تعديل نصوصها.
9. لاختبار الاشتراكات: افتح **إدارة المنصة → إنشاء مشترك جديد**، وأدخل اسم الأخصائي وبريده وكلمة مرور لا تقل عن 10 أحرف. بعد الإنشاء راجع جدول **المشتركون والاشتراكات**، ثم جرّب تسجيل الدخول بحساب الأخصائي.
10. عند اقتراب أو انتهاء الاشتراك، يظهر تنبيه وزر «طلب التجديد» داخل حساب المستخدم. يظهر الطلب في **طلبات تجديد الاشتراكات** بلوحة ندي، وتستطيع تجديد 30 يومًا، أو استخدام زر التفعيل/التجديد من جدول المشتركين مباشرة.

## الملفات اللازمة عند الرفع إلى GitHub
- `src/App.tsx` — الواجهة، إنشاء المشتركين، عرض الاشتراكات، طلبات التجديد، واستيراد JSON
- `src/programImport.ts` — مدقق البيانات ومستورد Firestore الدفعي، ومانع تكرار البرامج والأهداف
- `src/styles.css` — تصميم الإضافات بنفس ألوان المنصة
- `firestore.rules` — أمان إنشاء المشترك وتجديده والاستيراد
- `tests/import-and-subscriptions.test.mjs` — اختبارات سلوك الاستيراد
